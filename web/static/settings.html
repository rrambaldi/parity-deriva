    what an export looks like
    
Two files a series, one a side:
      <instrument>_<tf>_<from>_<to>-ASK.csv and -BID.csv,
      e.g. eurusd_m5_20150101_20260920-ASK.csv. The instrument as eurusd or
      EUR_USD, the timeframe m1, m5, m15, m30, h1, h4 or d1, the two days as YYYYMMDD.

    
CSV: this header, then a row a candle. The timestamp is when the candle opens, in UTC
      milliseconds since 1970.

    
timestamp,open,high,low,close,volume
1420070400000,1.20985,1.21005,1.20962,1.20983,321.5

    
JSON, the same name ending in .json: an array of candles with the same fields,
      as objects or as rows in that order.

    
[{"timestamp": 1420070400000, "open": 1.20985, "high": 1.21005, "low": 1.20962, "close": 1.20983, "volume": 321.5}]
[[1420070400000, 1.20985, 1.21005, 1.20962, 1.20983, 321.5]]

    
Both are what dukascopy-node writes (-f csv, -f json,
      -f array); -v adds the volume, which the import needs, and
      -fn gives the name:

    
npx dukascopy-node -i eurusd -from 2015-01-01 -to 2026-09-20 -t m5 -v -f csv -p ask -fn eurusd_m5_20150101_20260920-ASK
npx dukascopy-node -i eurusd -from 2015-01-01 -to 2026-09-20 -t m5 -v -f csv -p bid -fn eurusd_m5_20150101_20260920-BID

    
A long M1 or M5 series is better as CSV: a JSON is read whole into memory.

"""
MY-EMA: a pullback to the fast EMA, in the trend of the slow one.
"""

from parity_deriva.lib.streaming import Series
from parity_deriva.strategy.H4 import H4, bearish, bullish


class MyEma(H4):
    TAG = 'MY-EMA'
    INSTRUMENT = 'EUR_USD'
    GRANULARITY = 'H1'
    DESCRIPTION = (
        "Long above the EMA 200 when a bar's low touches the EMA 50 and it "
        "closes green, short the mirror. Stop 2 ATR(14) from the close, "
        "target 2R.")

    PARAM_HELP = {
        'fast': 'period of the fast EMA, in bars',
        'slow': 'period of the slow trend EMA, in bars',
        'atrStop': 'stop distance from the close, in ATR',
        'reward': 'target as a multiple of the stop (R)',
    }

    def setup(self, args):
        self._set(args, 'fast', 50)
        self._set(args, 'slow', 200)
        self._set(args, 'atrStop', 2.0)
        self._set(args, 'reward', 2.0)

    def series(self):
        return Series(ema=(self.fast, self.slow), atr=self.atrPeriod)

    def signal(self, state, candle):
        fast, slow, atr = state.ema(self.fast), state.ema(self.slow), state.atr()
        if fast is None or slow is None or not atr:
            return None
        close = candle.mid['c']
        if close > slow and candle.mid['l'] <= fast and bullish(candle):
            stop = close - self.atrStop * atr
            return 1, stop, self.levels(candle, 1, stop, self.reward)
        if close < slow and candle.mid['h'] >= fast and bearish(candle):
            stop = close + self.atrStop * atr
            return -1, stop, self.levels(candle, -1, stop, self.reward)
        return None

    

      
file name
the draft's name: MY-EMA.py is MY-EMA, and
        MY-EMA@2.py, as download names it, the next version of MY-EMA

      
class
exactly one, a subclass of H4 - or of
        M15, richer for intraday entries - or of a strategy to build on.
        Its name is its own: one another strategy's class has is refused, and only the
        versions of one draft share it

      
INSTRUMENT, GRANULARITY
what it is meant for

      
DESCRIPTION
its rules in plain words, for who reads the code

      
setup
every number to tune read with self._set(args, name, default):
        they are the parameters of the simulations, and PARAM_HELP says what each is

      
series
what the bars keep: Series of
        parity_deriva.lib.streaming, EMAs, SMAs, ATR, RSI…

      
signal
called on every closed bar: None, or
        (side, stop, target) - side 1 long or −1 short, stop and target as
        prices. The entry is at market on the next bar's open, one position at a time

      
imports
numbers (math, numpy…) and the parts of parity_deriva a
        strategy is made of; files, network, processes, eval and exec are refused

    

    
The server ends the file with a PARITY_DERIVA line, its version: leave it.
      A file the same as its draft's newest version is refused: there is nothing new in it.
      A draft is only backtested in a sandbox, until it is enabled here after reading its code.

  





  

    

    

      
      
    

  





  

    

      
calendar file format

      
a CSV · four columns · a row an event · times in UTC

    

    

      
    

  

  

    
time,currency,impact,title
2015-01-09 13:30:00,USD,high,Non-Farm Employment Change
2015-01-09 13:30:00,USD,high,Unemployment Rate
2015-01-22 12:45:00,EUR,high,Main Refinancing Rate
2015-01-22 13:30:00,USD,medium,Unemployment Claims
2015-12-25 00:00:00,GBP,non-economic,Bank Holiday

    

      
time
when it is released, in UTC: YYYY-MM-DD HH:MM:SS

      
currency
the currency it is about, in three letters: USD, EUR, GBP, JPY…

      
impact
high, medium, low or
        non-economic (holidays, speeches with no number): the source's own
        rating, kept as it is

      
title
the event's name as the source gives it, in quotes when it has a comma

    

    
The header line comes first, with the columns in any order; other columns are left out.
      An event is its time, currency and title: one already held is kept as it is and not
      added twice, so stretches of weeks that overlap import safely.

    
The collector writes this file, calendar.csv, when its push is refused.
      Any other source works once its export is put in these four columns.
